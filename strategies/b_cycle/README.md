# B 周期信号交易 v1

这是全行情检验后的独立 B 方向交易入口。A 仅用于 A-B 周期拟合，不下 A 订单。
它不沿用 baseline 的双边做市报价，也不是 Pair 的双腿套利。

## 从项目根目录运行

不开盘时检查配置（不连接交易所）：

```powershell
python -B strategies/b_cycle/run.py --check
```

使用已有盘口做离线运行：

```powershell
python -B strategies/b_cycle/run.py --replay data/market/philips_20260910T085700_968660Z_ad33f82a/orderbooks_00001.jsonl.gz --duration 800
```

开盘后连接模拟交易所并真实发送 IOC：

```powershell
python strategies/b_cycle/run.py --live
```

直接运行不带参数等同于 `--check`。`--live` 和 `--replay` 互斥。
先停止旧 baseline/pair/hybrid 进程。新模式要求整个账户仓位为零、可交易品种没有挂单，
不自动接管或清掉旧策略仓位。与其他策略并行运行会破坏账户归属，不能同账号同时运行。

## 交易规则

- 固定 180 秒周期、15 秒预测，逐步更新模型，只使用当时可见的 A/B 盘口。
- 用预测 B 变化乘拟合权重；绝对优势必须超过两股可执行完整价差、1 tick 缓冲和预计双边手续费。
- 每次最多 2 股，同时仅一笔 B 仓位；确认部分成交后不补仓。
- 入场等待至少 0.25 秒，最多再等 1 秒。发送前刷新盘口，用冻结目标价重新检查剩余优势，
  并将 IOC 最差允许价限制在优势仍为正的范围。这比研究脚本仅检查 VWAP 更严格。
- 持仓从入场订单发送前的本地单调时钟开始计时，约 15 秒后退出，普通退出另等待至少 0.25 秒。
  同步 RPC、行情缺失和撮合不确定性可使实际持仓更长。
- 周期短暂失效不立刻平仓。超过持仓期限后，退出意图保持；新鲜深度不足时等待，不继续入场。
- 每个品种价格按实际 tick 检查。盘口最多陈旧 1 秒，最大扫单距离 10 ticks；
  沿用研究情景，对最优侧累计预留 200 股深度。预留是保守容量折扣，不声称准确识别自身订单。
- 默认不开每股固定止损（`stop_per_share: null`）；可配置正数开启。账户累计损失 50 或从高点回撤 60
  时停止入场并立即尝试退出。它们是触发阈值，不能保证损失不超限。
- 默认运行 1,800 秒，末尾 30 秒禁止新入场并退出已有仓位。Ctrl+C 也停止入场并尝试退出，
  正常退出最多额外等待 5 秒；不能中断已经阻塞的同步 RPC。

参数在 [config.json](config.json)。当前入口把仓位最多限制为 2，持仓期限固定为已检验的 15 秒，
修改为更大仓位或其他期限会校验失败。`--duration` 可覆盖会话时长，需大于 closeout。

## 执行与重启

复用 common.Executor：记录发送、订单回执、私有成交、仓位变化、结算状态。
完全成交必须由私有成交和实际仓位共同确认。离线模拟器可明确证明 IOC 终态；
当前真实客户端接口没有同等的零/部分成交终态证明。
因此 live 的零成交、部分成交、超时或不明回执仍可能触发 hard fault，禁止后续任何插单，
包括自动平仓，防止重复执行与迟到成交冲突。此时日志明确保留剩余仓位，程序非零退出。
新策略没有把这个已知接口限制假装解决。

默认状态文件为 `state/default/b_cycle.json`，带 OS 锁。发任何交易前持久化“不允许自动重启”标记。
只有正常、确认空仓、无执行故障、未触发账户风险停止的退出，才标为允许下次启动。
崩溃、未确认 IOC、剩余仓位或风险停止后，启动会拒绝；须先对账处理，不能通过删除文件或换路径绕过。
此文件记录启动许可和结束结果，不提供非零仓位恢复。`--state-file` 仅供明确的独立账户路径使用。

## 数据与离线边界

日志位于 `data/runs/b_cycle/<run_id>/events.jsonl`，manifest 保存当前配置和 CycleSettings。
live 行情沿用同一连接采样到 `data/market/` 并关联至 manifest。
主要事件包括 `b_signal`、`b_entry_pending`、`b_entry_confirmed`、`b_holding`、`b_exit_intent`、
`b_entry_blocked`、`b_exit_blocked`、IOC 结算事件和 `session_end`。

replay 使用同一 Engine 和 IOC 执行器，`--fill-fraction` 默认 0.5，模拟可访问显示深度的比例，
同一盘口不会重复补充已消耗深度。原始历史盘口包含旧策略行为，实际新策略不保证获得同样成交。
录制末尾不捏造未来盘口或自动按中间价平仓；未平仓时保留仓位并返回退出码 2。
损坏/截断的 gzip 默认报错，不静默认定回放完整。可以用完整录制或在有效记录结束前设置 duration。

研究报告的收益不能直接当成此入口收益：这里新增账户风险阈值、会话退出、IOC 回执核对，
并使用更严格的最差成交价保护及独立模拟器的可访问深度。

## 验证

```powershell
python -B -m unittest discover -s tests -v
```

本次 47 项测试通过（含 11 项 B 周期策略测试），覆盖入场重检、不加仓、仅 B 交易、期限退出、
缺失盘口、风险停止、旧仓位拒绝、已确认部分成交、未知 IOC 禁止重试及回放末尾残余仓位。
历史入口集成检查：9 月 10 日录制运行 800 秒、9 月 9 日录制运行 1,800 秒，均完成交易并确认空仓，
未出现未决 IOC。这是离线实现检查，不是实盘成交或新样本盈利证明。
