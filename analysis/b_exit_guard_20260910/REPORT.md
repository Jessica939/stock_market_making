# B 小仓位减仓价格保护：离线实验

结果支持把“小仓位退出报价过于靠近中心”作为下一步验证方向，但尚未证明修改后会盈利。当前版本中，新规则会挡住 123 笔原有纯减仓成交；这些成交的后续价格表现较差，且多数样本随后较快出现过满足新限价的盘口。等待期间也存在显著的不利波动，因此不能把报价改善直接加到原收益上。

本实验仅写入独立分析目录，没有连接交易所。运行前后核对了 baseline 策略 Python、notebook 及 order_execution.py 的 SHA-256，内容未变。

## 实验规则

- 仅针对 PHILIPS_B，报价时绝对持仓为 1—10 股、周期信号有效且不处于 reduce_only 状态。
- 持有多仓时，减仓卖价至少为原中心价 + 3 tick；持有空仓时，减仓买价至多为原中心价 − 3 tick。按 tick 向外取整，并保持不穿过原对手盘。
- 只将原减仓报价向外调整；原来更宽的报价、单量、增仓报价及其余字段保持原值。
- 1 tick = 0.1；3 tick 借用现有增仓保护的距离，10 股是尚未校准的实验边界，没有扫描参数寻找最佳历史结果。

这不是“从持仓成本价保证盈利退出”，也没有规定固定持仓时间。后文的 1—15 秒仅为历史价格观察窗口，并非已实施的等待规则。

## 当前版本的结果

主样本：baseline_cycle_risk_only_v2，北京时间 2026-09-10 17:11:54—17:18:03，约 6.14 分钟。该窗口原始 B 交易现金流为 −147.6，起止持仓均为 0，最高绝对持仓为 6 股；这些是旧策略的真实记录，不是新规则的模拟收益。

| 指标 | 结果 |
|---|---:|
| 原始 B 报价决策 | 655 次 |
| 新规则改变减仓价格 | 259 次（39.5%） |
| 上述报价向外移动 | 平均 1.52 tick，中位数 2 tick，最大 2 tick |
| 全部原始成交，且匹配到原始订单报价 | 365 笔 |
| 实际减仓数量（含跨零成交的减仓部分） | 314 股 |
| 纯减仓成交 | 157 笔 / 312 股 |
| 新限价会阻止的纯减仓成交 | 123 笔 / 257 股 |
| 其余纯减仓成交 | 34 笔 / 55 股 |

存在 2 笔跨越零仓位的成交，其减仓部分合计 2 股；不把它们的全部数量计入纯减仓组。另有 2 笔成交所属订单虽会被改价，但原成交价依然满足新限价，不能称为新规则会挡住的成交。报价改动使用“新限价减原限价”计算，不能用原成交价替代原限价；成交价改善不算本实验贡献。

以原成交价与成交后 5 秒中间价比较，买入用“未来中间价 − 买价”，卖出用“卖价 − 未来中间价”，按成交数量加权：

| 纯减仓分组 | 5 秒有效数量 | 每股后续价格表现 |
|---|---:|---:|
| 新限价会挡住的成交 | 253 股（121 笔） | −0.888 |
| 其余成交 | 53 股（33 笔） | −0.136 |

受影响组的 15 秒结果为 −0.970 / 股，覆盖 249 股。这说明规则触及的原成交质量较差，不能说明这些成交消失后会省下相同金额。这个样本已经用于发现问题，属于样本内诊断。

## 原退出之后，是否出现过更好的价格

以每笔受影响成交的原退出时刻为起点，固定其新限价，检查随后历史盘口：平多要求买一价不低于新卖价，平空要求卖一价不高于新买价，同时该档显示数量至少覆盖原成交数量。当前 123 笔均有完整窗口；要求窗口两端有快照、终点快照迟到不超过 1 秒、观察间隔不超过 2 秒。

| 原退出后的观察窗口 | 出现满足价格和数量的对手盘 | 按原成交量加权比例 | 同方向主动成交达到目标价的比例 |
|---|---:|---:|---:|
| 1 秒 | 99 / 123（80.5%） | 84.8% | 84.6% |
| 3 秒 | 115 / 123（93.5%） | 96.1% | 94.3% |
| 5 秒 | 117 / 123（95.1%） | 96.9% | 98.4% |
| 15 秒 | 120 / 123（97.6%） | 98.8% | 99.2% |

3 秒内达到条件的 115 笔，首次观察到达标的时间中位数为 0.401 秒。这里的比例是历史报价或成交到达比例，**不是新策略成交率**。主动成交指标只检查方向和价格，不要求单笔数量覆盖原单量。

盘口是历史聚合数据，可能包含自身订单；没有重建纯外部可执行深度。原订单已退出之后的行情也不是延迟退出后的真实反事实行情。实验没有模拟排队、撤改单、延迟、动态重新定价以及候选订单对市场的影响，也没有把受影响原成交之前可能发生的新成交补入。

## 等待的风险

以原退出价为基准，统计整个观察窗口内对手盘的最大不利变化：平多看买一价下跌，平空看卖一价上涨，负值截为 0。

| 窗口 | 每股最大不利变化的 95% 分位 | 样本最坏值 |
|---|---:|---:|
| 1 秒 | 0.60 | 2.20 |
| 3 秒 | 1.89 | 2.30 |
| 5 秒 | 2.20 | 3.00 |
| 15 秒 | 3.20 | 4.20 |

这是完整窗口的价格风险描述，包括目标价已经出现之后的波动；不是实际持有到退出的最大损失，也不是新策略回撤。报价一般只改善 0.1—0.2，少数不利行情的幅度可以大得多。不能只看多数样本很快达标而忽略剩余样本。

另做一个机械仓位敏感性检查：将这 123 笔退出数量统一延迟，其余原成交完全保留，按时间重新累加持仓。

| 延迟 | 最高绝对持仓 |
|---|---:|
| 0 秒 | 6 股 |
| 1 秒 | 7 股 |
| 3 秒 | 10 股 |
| 5 秒 | 10 股 |

四种情形都未超过用户给定的 100 股限制，最终仍为 0。该检查不保证新策略持仓也如此：真实延迟会改变后续增减仓判断、报价及成交数量，未成交订单还需占用风险额度。它不是最大风险上界，没有计算反事实收益。

## 对策略的具体含义

优先保留本次候选规则用于进一步完整回放：小仓位退出价格也设置最低距离。现有证据不足以选择最优距离、10 股边界或最佳超时，更不足以认定应延长所有仓位的持有时间。

下一阶段完整回放需要把挂单存续、撤改单、部分成交、仓位变化以及增仓报价一并更新，并比较原策略、价格保护、价格保护加有界等待三种情形。1 秒与 3 秒可作为待检验的超时情形，库存变大或原风险退出条件触发时要沿用风险优先逻辑。评估指标应为扣除适用费用后的完整收益、尾部损失和风险占用，而不是把未来中间价当作退出价。

## 文件与复现

- guard.py：独立候选报价函数，未接入交易策略。
- attribution.py：区分原单改价、原成交仍可接受、实际纯减仓。
- evaluate.py：原订单关联、报价改动、后续盘口及机械库存敏感性分析。
- metrics.json：四份运行的统计、逐事件机会记录、原始日志和策略文件哈希。
- quotes.jsonl / fills.jsonl：逐报价及逐成交归因。
- test_guard.py：7 项检查，覆盖单侧改价、边界和回退、价格取整、价格改善成交及跨零成交。

```text
python -m unittest discover -s analysis/b_exit_guard_20260910 -p test_guard.py
python analysis/b_exit_guard_20260910/evaluate.py
```

本报告只分析本地竞赛记录，不依赖在线市场信息，也没有根据空白 buyer/seller 字段推断成交对手身份。
